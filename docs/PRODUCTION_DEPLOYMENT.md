# NexusHR public deployment runbook

## Hosting topology

- Frontend: Vercel, project root `frontend`, Vite build command `npm run build`, output `dist`.
- API: Render Docker Web Service using `backend/Dockerfile`, health check `/actuator/health`.
- Database: Render managed PostgreSQL, attached only to the NexusHR API.
- Database migrations: Flyway V1–V6 run on API startup under the `prod` profile; Hibernate uses `validate`, not schema creation.

## Before connecting GitHub

- Review source and remove any real secrets from all history, not just the current files. Rotate any secret that was ever committed.
- Use a new repository; do not push unrelated NexusHR production copies or MergKart.
- Confirm `.gitignore` excludes `.env*` (except `.env.example`), `node_modules/`, `target/`, runtime DB files, and logs.
- Check hosting plan pricing, region, sleeping/idle behavior, database storage, backups, and retention. The included Render blueprint uses a paid database/service plan; change only after understanding the trade-offs.

## Render API and PostgreSQL

1. Create a Render Blueprint from the repository and inspect the plan/region/resource list before applying it. `render.yaml` creates one managed PostgreSQL database and one API service.
2. Set `CORS_ORIGINS` to the exact public frontend origin, with no trailing slash. Multiple origins may be comma-separated.
3. Set `BOOTSTRAP_ADMIN_EMAIL` and a unique `BOOTSTRAP_ADMIN_PASSWORD` of at least 12 characters before first startup. Store the password in a password manager; never commit it or paste it into chat.
4. `JWT_SECRET` is generated by Render's blueprint. Do not replace it with a short or shared value.
5. Confirm the Render service is healthy at `/actuator/health`. Inspect startup logs and verify Flyway reports V1 through V6 successfully.
6. Sign in as the bootstrap admin, then remove both bootstrap environment variables. Bootstrap creates an Admin only when no Admin account exists. If the configured email belongs to an existing non-admin account, startup fails rather than promoting or overwriting that account. If an Admin already exists, bootstrap skips creation.

## Vercel frontend

1. Import the repository into Vercel and set Root Directory to `frontend`. Framework preset: Vite. Build command: `npm run build`; output directory: `dist`.
2. Set `VITE_API_URL` to `https://YOUR-RENDER-API.onrender.com/api` for the Production environment. Do not include a trailing slash.
3. Deploy a preview first. Test login and API calls. Then add the preview origin to Render `CORS_ORIGINS` only if you intend to keep preview access.
4. Deploy production and update Render `CORS_ORIGINS` to the exact production Vercel domain. Redeploy the API after changing it.

## Release gates (must all pass)

- [ ] `mvn clean test` passes on Java 21.
- [ ] `npm ci` and `npm run build` pass from a clean checkout.
- [ ] Render health endpoint returns HTTP 200.
- [ ] Flyway V1–V6 complete on a fresh managed PostgreSQL database.
- [ ] Production database survives API restart and redeploy.
- [ ] Bootstrap Admin can log in; bootstrap variables are then removed.
- [ ] Invalid credentials and invalid/expired JWTs are rejected.
- [ ] Admin, HR, Manager, Employee permissions are verified against the API (not just hidden UI navigation).
- [ ] Employee profile, team scoping, salary/payroll access and user management are verified for data leakage.
- [ ] Attendance check-in/out, duplicate operations, corrections and audit history are verified.
- [ ] Leave request, manager approval and HR/Admin final approval are verified.
- [ ] Payroll, performance, recruitment, holidays, announcements and notifications are verified end-to-end.
- [ ] Browser console and network panel show no uncaught errors, failed API calls, mixed-content errors or CORS errors.
- [ ] Database backup/restore and rollback plan are documented before real data is entered.

## Limitations to disclose

The existing onboarding workflow does not implement email invitations, temporary-password delivery, or mandatory password change. There is no configured mail provider in this project. Payroll calculations are illustrative and must not be used for statutory payroll. The README's AI insights are deterministic heuristics, not a trained predictive model. This deployment is appropriate for a portfolio/demo evaluation only after all release gates pass; it is not security/compliance certification for real employee records.
